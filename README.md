# linux-settings

Локальный репозиторий с настройками для Fedora Workstation 45, GNOME Wayland и
терминала Ptyxis. Скрипт запускается обычным пользователем из графической
сессии, без `sudo`.

## Что настраивается

| Настройка | Поведение |
|---|---|
| Раскладка | `Alt+Shift` переключает уже добавленные раскладки. В `org.gnome.desktop.input-sources xkb-options` добавляется `grp:alt_shift_toggle`; остальные XKB-опции и список языков не меняются. |
| Терминал | Глобальный `Alt+T` запускает `ptyxis --new-window --maximize`: открывается новое развёрнутое окно, а не вкладка и не полноэкранный режим. Используется пользовательский ярлык GNOME (`org.gnome.settings-daemon.plugins.media-keys`). |

## Требования

- Fedora Workstation 45, GNOME Wayland, Ptyxis.
- `gsettings` и `ptyxis` в `PATH`.
- Запуск из графической сессии обычным пользователем.

## Использование

```bash
cd ~/linux-settings
./settings.sh status
./settings.sh apply
./settings.sh undo
```

### `status`

Только читает настройки и показывает:

- текущие `xkb-options` и наличие `grp:alt_shift_toggle`;
- настроен ли `Alt+T`, какой ярлык за него отвечает и кто его создал;
- занят ли `Alt+T` другим пользовательским ярлыком.

Команда ничего не записывает, включая файл состояния.

### `apply`

1. Проверяет наличие `gsettings`, `ptyxis` и схемы пользовательских ярлыков.
2. Проверяет, не занят ли `Alt+T` другим пользовательским ярлыком.
3. Добавляет `grp:alt_shift_toggle` только если его ещё нет, сохраняя остальные
   XKB-опции.
4. Использует уже существующий подходящий ярлык или создаёт свой в свободном
   слоте `customN`.

Список `custom-keybindings` не перезаписывается: новый путь добавляется к нему.
Слот `custom0` не считается свободным. Повторный `apply` не создаёт дубликатов;
если обе настройки уже сделаны вручную, скрипт ничего не меняет.

### `undo`

Убирает только то, что добавил скрипт:

- удаляет `grp:alt_shift_toggle`, сохраняя остальные XKB-опции;
- удаляет созданный им ярлык из списка и сбрасывает его поля.

Если настройка была до первого `apply` или созданный ярлык потом изменили
вручную, `undo` оставляет её как есть.

Сведения о сделанных изменениях хранятся вне репозитория:

```
${XDG_STATE_HOME:-$HOME/.local/state}/linux-settings/state.sh
```

Повторный `apply` не стирает этот файл.

## Ручная проверка

1. Выполнить `./settings.sh status` и убедиться, что обе настройки отображаются
   ожидаемым образом.
2. Выполнить `./settings.sh apply`.
3. Переключить раскладку `us`/`ru` сочетанием `Alt+Shift` (если оба языка уже
   добавлены в GNOME).
4. Дважды нажать `Alt+T`. Должны открыться два новых развёрнутых окна Ptyxis,
   а не две вкладки и не полноэкранный режим.
5. При необходимости выполнить `./settings.sh undo` и проверить, что остальные
   XKB-опции и пользовательские ярлыки не пострадали.

## Проверка синтаксиса

```bash
bash -n settings.sh
```

## Безопасная проверка на изолированном профиле

Чтобы не менять настройки рабочего стола, запись можно проверить с отдельным
GSettings-профилем:

```bash
tmp_config=$(mktemp -d)
tmp_state=$(mktemp -d)
GSETTINGS_BACKEND=keyfile \
XDG_CONFIG_HOME="$tmp_config" \
XDG_STATE_HOME="$tmp_state" \
./settings.sh apply
```

После проверки временные каталоги можно удалить.

Репозиторий локальный: remote не настраивается, в публикацию не отправляется.
